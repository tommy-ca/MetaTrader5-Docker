# MT5 Bridge Security and Reliability Hardening

## Problem symptom
- MetaTrader 5 (MT5) Docker containers experience "silent crashes" or become unresponsive during high activity.
- RPyC connectivity fails in environments where the host or client runs RPyC v6.0 or higher.
- Redundant logic between the `demo.py` script and the Docker `HEALTHCHECK` leads to inconsistent troubleshooting.
- Machine-readable diagnostic output (JSON logs) exposes sensitive information like MetaTrader account numbers (login) and filesystem paths.

## Root cause analysis
- _Wine IPC deadlocks_: Headless Wine environments require significant shared memory (`/dev/shm`) for inter-process communication between the `wineserver` and application processes. The Docker default (64 MB) is insufficient for MT5.
- _Zombie process accumulation_: Wine often generates sub-processes (e.g., `mscorsvw.exe`) that don't terminate cleanly, eventually exhausting container process limits without an `init` process.
- _RPyC v6 security policy_: RPyC v6.0 introduced a breaking change that disables access to public attributes by default. This prevents `mt5linux` from accessing MT5 object properties like `bid` or `connected`.
- _Incomplete sanitization_: Diagnostic scripts lacked a proactive filtering layer to scrub PII or internal environment paths from the `terminal_info` dictionary.

## Working solution

### 1. Infrastructure hardening
Update `docker-compose.yaml` to include an `init` process and expand shared memory to two GB.

```yaml
services:
  mt5:
    image: gmag11/metatrader5_vnc
    init: true      # Reaps zombie processes generated by Wine-MT5
    shm_size: 2gb   # Prevents Wine crashes during heavy memory allocation
```

### 2. RPyC v6 compatibility
Enable `allow_public_attrs` in the `mt5linux` configuration to maintain compatibility with modern RPyC environments.

```python
from mt5linux import MetaTrader5

# Required configuration for RPyC v6 compatibility
config = {
    "allow_public_attrs": True, 
    "sync_request_timeout": 30
}

mt5 = MetaTrader5(host="localhost", port=args.port, config=config)
```

### 3. Unified validation logic
Consolidate redundant logic into `scripts/validate_connectivity.py` using a monotonic clock and exponential backoff for robust initialization.

```python
import time

def validate(host, port, timeout=60):
    mt5 = MetaTrader5(host=host, port=port, config={"allow_public_attrs": True})
    
    # Use monotonic clock with exponential backoff for robust retries
    start_time = time.monotonic()
    delay = 0.5
    while time.monotonic() - start_time < timeout:
        if mt5.initialize():
            break
        time.sleep(delay)
        delay = min(delay * 2, 5) # Backoff to max 5s
```

### 4. Privacy sanitization
Implement an allow-list approach to filter sensitive keys from MT5 diagnostic objects before they are logged.

```python
# Allow-list approach for maximum security
info = mt5.terminal_info()
info_dict = info._asdict() if hasattr(info, "_asdict") else {}

safe_fields = ["connected", "trade_allowed", "company", "build", "name"]
sanitized_info = {k: v for k, v in info_dict.items() if k in safe_fields}
```

## Prevention strategies
- _Host-level port binding_: Always map the RPyC bridge (port 8,001) to `127.0.0.1` on the host side to prevent unauthenticated remote code execution.
- _Monotonic timing_: Use `time.monotonic()` for connection timeouts to prevent issues with system clock adjustments.
- _Agent-native diagnostics_: Include a `remediation` field in JSON output (e.g., "Check VNC port 3,000.") to allow autonomous agents to resolve issues without deep investigation.
